# High CPU

Use this runbook when CPU usage on a server stays above 75% for more than 5 minutes. Between 75% and 90% with normal latency it is a warning: watch the trend. At 100% for 15 minutes or more, or when request latency and timeouts rise, it is critical. Find the busy processes with `top` or `ps -eo pid,comm,%cpu --sort=-%cpu | head`, and check the load average against the number of cores with `uptime` and `nproc`. Compare the start of the spike with recent deploys, cron jobs, and traffic graphs. If one runaway process (stuck job, infinite loop) is the cause, propose a restart of that process or service; restarts need human approval. If the load is real traffic, scale out by adding instances behind the load balancer. If a recent deploy caused it, roll back. Do not restart a whole server just because CPU is high.
