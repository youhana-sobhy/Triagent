# Database disk full

Use this runbook when disk usage on a database server (PostgreSQL data directory such as /var/lib/postgresql) goes above 85%. Above 90%, treat it as critical: when the volume reaches 100%, PostgreSQL cannot write WAL or data files, rejects writes, and may shut down. First confirm with `df -h` and find what is growing with `du -sh /var/lib/postgresql/*/main/*`. The most common cause is WAL piling up in `pg_wal` because a replication slot is inactive or archiving is failing; check `SELECT slot_name, active FROM pg_replication_slots;`, drop slots that are no longer used, and fix `archive_command` so old WAL files can be removed. Then clean safe targets: old logs in the log directory, and old backups or dumps stored on the same disk. Never delete files inside `pg_wal` or `base` by hand. If usage is still above 85% after cleanup, expand the volume and grow the filesystem. Escalate to the database on-call if writes are already failing.
